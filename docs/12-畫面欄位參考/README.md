## 撰寫規範

### 資料一律來自程式碼，不寫臨床意義

🔴 **只寫程式碼查證得到的事實**：欄位名稱、控制項型別、繫結屬性、下拉選項、顯示條件、按鈕行為。

**不寫**「這個欄位在臨床上代表什麼」——那需要臨床知識，從欄位名推測出來的說明**看起來完全正常卻可能是錯的**，比不寫更危險。需要臨床意義請找研究團隊補，補上時標明來源。

### 固定章節

| 章節 | 必備 | 內容 |
| --- | --- | --- |
| 畫面基本資料 | ✅ | 路由、頁面權限、頁籤清單、頁面標題 |
| 共通行為 | ✅ | 編輯／檢視模式、Visit Code 切換、儲存與取消、操作歷程分類 |
| **欄位**章節 | ✅ | 每個欄位一列。標題**只要含「欄位」**即可（`欄位表`、`查詢條件欄位`、`編輯表單欄位`、`顯示欄位` 都通過檢查）——貼合該畫面比統一字面重要 |
| **條件顯示規則**章節 | ✅ | 選什麼值會讓哪些欄位出現或消失。**沒有條件顯示就寫「無」**，不要略過章節 |
| 頁籤：`{名稱}` → 按鈕 | ❌ | 該頁籤沒有按鈕就不寫 |
| ⚠️ 已知問題 | ❌ | 查到才寫 |

### 欄位表的固定欄位

| 欄位名 | 說明 |
| --- | --- |
| **畫面標題** | 逐字抄自 `.razor` 的表頭文字（含拼字錯誤與全形符號，**不要修正**） |
| **控制項** | 文字框（`SfTextBox`）／日期（`SfDatePicker`）／下拉（`SfDropDownList`）／唯讀 |
| **繫結屬性** | `data.XXX`，可回頭在原始碼搜尋 |
| **可選值** | ⭐ 下拉一律逐字抄 `DropDownListDataService` 對應的 `Get*` 方法，**並標出方法名**，方法名就是回溯路徑 |
| **何時出現** | 「一律顯示」或「僅當 `{欄位}` = `{值}`」；另標明是否只在編輯模式出現 |

### 三條硬規則

1. ⭐ **下拉選項的唯一出處是 `CTMS.Business/Services/ClinicalInformation/DropDownListDataService.cs`**。文件不重新定義選項，只抄並標方法名。
2. ⚠️ **畫面標題逐字照抄**，包括 `Durg`（原始碼就是這樣拼）這類錯字。使用者是拿畫面上看到的字回來搜尋。
3. 🔴 **發現「畫面標題與繫結欄位對不上」「檢視模式顯示別的欄位」「條件永遠不成立」這類問題，一律寫進「已知問題」並標 🔴**。這些是靜默錯誤——畫面看起來正常，資料卻是錯的。

### 引用程式碼的方式

用**符號名**（`SurgeryView`、`data.Uterus`、`GetTumorNumber()`），不要用行號。行號改一次就全錯，而且沒有任何檢查抓得到。
