## 2. 結論

目前程式碼與資料檔「不完全符合」當初新增三家醫院的完成需求。

核心程式架構大致已依做法 B 改為 `HospitalRegistry` 集中化，柳營奇美、高榮、嘉長三家醫院也已在 registry 中定義；院別下拉、新增病患 prefix 對應、Dashboard、SubjectNo/抽血/CSV 等主要流程多數符合預期。

但仍有兩個實質缺口（**兩項均已於後續修復，見下方更新註記**）：

1. 高榮與嘉長的隨機表資料沒有落地到 `RandomList.xlsx`，目前 runtime JSON 也沒有 `KSVGH` / `CYCGMH` 的隨機清單。→ 已於 2026/07/09～07/10 修復。
2. `EnrollmentProgressService` 仍維持舊三院硬編碼，高榮與嘉長會被列入未分類。→ 已於 2026/08/04 修復。

> **更新（2026/07/09）：** 上述第 1 項（隨機表）**已修復**——已補齊 `高榮Early/高榮Advance/嘉長Early/嘉長Advance` 四個分頁，並在 `tests/e2e/tests/random.spec.ts` 加入「分頁實際載入 80/320 列」的內容斷言，E2E **13 項全數通過**。詳見《AI自動化測試-隨機表缺口修復記錄》。第 2 項（EnrollmentProgress）仍為已知缺口。
>
> **更正（2026/07/10）：** 07/09 初版曾以固定種子產生「各自獨立序列」，**此做法有誤**——隨機表由統計專家提供、系統不得自行以亂數產生。已更正為：**高榮、嘉長四個分頁完全複製奇美（順序、內容皆相同）**；並新增 `tests/e2e/tests/random-activation.spec.ts` 驗證「填癌別＋分期後 SubjectNo 才上隨機表」的啟用規則。
>
> **更新（2026/08/04）：** 上述第 2 項（`EnrollmentProgressService`）**已修復**——交付前已改用 `HospitalRegistry.PrefixOwners` 與 `NormalizeToOwnerShortName()`，`/EnrollmentProgress` 表頭改為 5 家（成大、奇美、郭綜合、高榮、嘉長），與儀表板同一套歸戶邏輯；`tests/e2e/tests/enrollment-progress.spec.ts` 已同步改為驗證 5 家表頭並新增「柳營奇美不單獨成欄」案。**本報告的兩項缺口至此全部結清。**

## 3. 已符合項目

### 3.1 HospitalRegistry 定義符合需求

`src/CTMS/CTMS.Share/Helpers/HospitalRegistry.cs` 已集中定義六筆院別：

- 成大醫院：`NCKUH`
- 奇美醫院：`CHIMEIH`
- 郭綜合醫院：`KGH`
- 柳營奇美醫院：沿用 `CHIMEIH`，`IsPrefixOwner = false`
- 高雄榮民總醫院：`KSVGH`
- 嘉義長庚紀念醫院：`CYCGMH`

其中柳營奇美的行為符合文件決策：只參與院別下拉與院別轉 prefix，流水號、隨機表、抽血檔、儀表板皆歸奇美。

### 3.2 院別下拉與新增病患 prefix 對應符合需求

`DropDownListDataService.Get院別()` 已改為讀取 `HospitalRegistry.All`，因此院別下拉會包含六筆院別。

`PatientService.AddEmptyAsync()` 已改為使用 `HospitalRegistry.GetByDisplayName(addNewPatientViewModel.院別)?.Prefix` 取得 prefix。預期結果如下：

- 柳營奇美醫院 -> `CHIMEIH`
- 高雄榮民總醫院 -> `KSVGH`
- 嘉義長庚紀念醫院 -> `CYCGMH`

### 3.3 Dashboard 已改為 registry 化

`DashboardService.Build()` 已由 `HospitalRegistry.PrefixOwners` 建立醫院清單與 `HospitalStats`，因此儀表板會列出五個 prefix owner：

- 成大
- 奇美
- 郭綜合
- 高榮
- 嘉長

`DashboardService.GetHospitalName()` 已呼叫 `HospitalRegistry.NormalizeToOwnerShortName()`，先用 `DisplayName` 精確比對，再 fallback 到短名 `Contains`。這可避免「高雄榮民總醫院」不含短名「高榮」而造成靜默漏算。

### 3.4 SubjectNo、抽血檔名、CSV 院名邏輯符合本次決策

以下邏輯已改為讀取 `HospitalRegistry`：

- `SubjectNoHelper.GetHospital()`
- `SubjectNoHelper.GetBloodFilename()`
- `RandomParameterMode.Parse()`
- `PatientSingleRowCsvExportService.ResolveHospital()`

柳營奇美使用 `CHIMEIH` prefix，因此這些依 SubjectNo prefix 反查的流程會將柳營奇美視為奇美，符合「院區群組層級」的本次決策。

### 3.5 文件編碼符合規範

已執行 `scripts/Test-DocsEncoding.ps1`，檢查結果顯示 `docs/` 下 `.md` 文件皆為 BOM=True 且 ReplacementCharacter=False。

## 4. 發現問題

### 4.1 RandomList.xlsx 缺少高榮與嘉長分頁

當初需求要求高榮與嘉長從奇美 Early/Advance 分頁複製內容，建立以下四個新分頁：

- `高榮Early`
- `高榮Advance`
- `嘉長Early`
- `嘉長Advance`

實際檢查 `src/CTMS/CTMS/Data/RandomList.xlsx`，目前只有以下分頁：

- `成大Early`
- `成大Advance`
- `奇美Early`
- `奇美Advance`
- `郭綜合Early`
- `郭綜合Advance`
- `預計收案人數`

缺少高榮與嘉長四個分頁。

影響：如果 runtime JSON 需要重建，或自癒補讀要補高榮/嘉長資料，`RandomListService` 會因缺分頁而略過高榮與嘉長，導致這兩院沒有可用隨機表資料。

### 4.2 RandomListRuntime.json 沒有 KSVGH / CYCGMH

實際檢查 `src/CTMS/CTMS/Data/RandomListRuntime.json`，目前只包含：

- `NCKUH`
- `CHIMEIH`
- `KGH`

沒有：

- `KSVGH`
- `CYCGMH`

影響：高榮或嘉長病患執行隨機分組時，`RandomGroupingService` / `RandomListService` 查不到對應醫院的可用 random item，分組結果可能維持 `NA`。

### 4.3 EnrollmentProgressService 仍為舊三院硬編碼（已於 2026/08/04 修復）

> ✅ **已修復**：`Build()` 改讀 `HospitalRegistry.PrefixOwners`、`GetHospitalName()` 改用 `HospitalRegistry.NormalizeToOwnerShortName()`。以下為修復前的原始記錄。

`src/CTMS/CTMS.Business/Services/EnrollmentProgressService.cs` 的 `Build()` 目前仍只建立三家醫院：

- 成大
- 郭綜合
- 奇美

`GetHospitalName()` 也只辨識成大、奇美、郭綜合。高雄榮民總醫院與嘉義長庚紀念醫院不會被歸到對應欄位，而會進入 `UnclassifiedCount`。

影響：收案進度統計頁會漏列高榮與嘉長，不符合新增醫院後相關統計頁應同步支援的需求。
