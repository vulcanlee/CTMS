# 收案進度統計頁 設計決議（2026-07-02）

## 背景

研究簡報有一頁「1-6. 收案進度」表格（醫院 × 癌別 × 期別 分層、對照組/實驗組 分組、小計、總計、期中/期末里程碑），過去需人工填寫。本次新增網頁 `/EnrollmentProgress`，直接顯示系統真實統計數據供截圖使用。

## 與使用者確認的需求決議

| 議題 | 決議 | 理由 |
| --- | --- | --- |
| 醫院範圍 | 只做成大、郭綜合、奇美三家 | 使用者明確指示；柳營奇美因名稱含「奇美」由既有 Contains 邏輯自然併入奇美 |
| 視覺風格 | 沿用系統既有（儀表板深色卡片）風格 | 使用者選擇不還原簡報配色 |
| 總計基準日 | 自動帶「今天」，民國年格式（例：115.07.02） | 截圖永遠是最新數字 |
| 里程碑列 | 期中 206 人（116.01）、期末 294 人（116.07）為固定文字寫死 | 研究計畫固定目標值，非系統統計 |
| 收案定義 | 只計 `Patient.狀態 == "收案"`（排除「退出」） | 與儀表板統計口徑一致，兩頁數字可互相對照 |
| 未隨機分組者 | 整筆不計入（含總計） | 表格每格都屬對照組或實驗組，未分組者無格可填；計入總計會造成「格子加總 ≠ 總計」的截圖矛盾 |
| 醫院/癌別/期別無法歸類者 | 不進表格，但以頁尾註記筆數 | 資料品質透明，避免靜默漏算 |
| 進入方式 | 只提供獨立網址，不加任何選單連結 | 使用者明確指示 |

## 採用做法

仿儀表板三層架構（Page → View → Service），但獨立於 `DashboardService` 之外：

- 新 Service 不做逐病人 AI 報告檢查（那是儀表板載入慢的主因），單純交叉計數。
- 歸類規則（醫院 Contains、FIGO 開頭由長到短比對、癌別 Contains）全部複用 `DashboardService` 的既有邏輯，確保兩頁口徑一致。

### 曾考慮並否決的替代方案

1. **擴充 `DashboardService` / 在 `/Dashboard` 頁內加區塊** — 否決：使用者要獨立網址方便截圖；且會把 48 格交叉統計耦合進已經偏慢的儀表板重算。
2. **完全還原簡報配色（綠/藍/黃 + 粉紅總計列）** — 否決：使用者選擇沿用系統風格。
